# SigmaPay requirements traceability

This table maps the source requirements to the current local demo implementation and records its limits. The requirements source is `SIGMAPAY_Requirments_FINAL V1.pdf`.

| Requirement | UI | API / implementation | Current scope |
| --- | --- | --- | --- |
| Account creation and login | `frontend-client/src/pages/AuthPage.tsx`, `LoginPage.tsx` | `POST /api/accounts/register`, `POST /api/accounts/login`, `POST /api/accounts/demo-login` | Passwords are scrypt-hashed. Data is process-local; no production session provider. |
| Profile, password, identity, 2FA, login activity | `frontend-client/src/pages/ProfilePage.tsx` | `/api/accounts/:userId`, `/username`, `/password`, `/verify`, `/2fa/*`, `/login-activity` | Identity and second factor are simulated. |
| Budgets, expense tracking, trends, alerts | `frontend-client/src/pages/BudgetPage.tsx` | `/api/budgets/create`, `/expense`, `/:userId`, `/:userId/trends`, `/:userId/alerts/check` | Activity is in memory in finance service. |
| Savings goals, contributions, progress and planning suggestion | `frontend-client/src/pages/GoalsPage.tsx` | `/api/goals/create`, `/:userId`, `/:goalId/progress`, `/:goalId/contributions`, `/recommendations` | Suggestions are illustrative; not generated by an AI provider. |
| Group savings and contribution tracking | `frontend-client/src/pages/GroupSavingsPage.tsx` | `/api/groups/create`, `/:groupId/member`, `/:groupId/deposit`, `/:groupId/report` | Group data is process-local in the savings service. |
| Reports and export | `frontend-client/src/pages/ReportsPage.tsx` | `POST /api/reports/:userId`, `GET /api/reports/:userId/export` | CSV export contains a report generated from the finance service's current transactions. |
| Bills and scheduled payments | `frontend-client/src/pages/BillsPage.tsx`, `PaymentsPage.tsx` | `/api/bills/*`, `/api/payments/*` | Payments are sandbox events; scheduled payments are not automatically executed. |
| Notifications and preferences | `frontend-client/src/pages/NotificationsPage.tsx` | `/api/notifications/*` | Alerts/preferences are local to the notifications service. No external delivery. |
| Local web deployment | `docker-compose.yml`, `gateway/nginx.conf`, Dockerfiles | Compose runs five domain APIs, gateway and frontend | Each service has its own in-memory store. |

## Storage and health

Repositories in `backend-server/src/data/repositories.ts` are in-memory. `GET /health` reports `database: memory`; it does not probe Supabase. `backend-server/src/config/supabase.ts` and `supabase/schema.sql` are not connected to active runtime repository operations. Supabase credentials should not be added to the front end and will not enable persistence in this version.

## Build verification

Run the backend and frontend builds from their folders using `npm ci && npm run build`. Validate the Docker topology with `docker compose config` and start it using `docker compose up --build`. Service startup and browser behavior are described in the root README.
